# 定位

DWS 后台观察与机器人交互以[钉钉接入设计](../design/dingtalk-integration-design.md)为准：观察评估后启动独立完整 Agent 自主调查，完成只记录；机器人仅 Owner 私聊与有效群 @ 直接交给各自人设 Agent，群内不因 Owner 发起而升权。主动沟通是独立、可审计的授权操作。本轮源码实现，离线验证已通过，尚未安装或真实发送。

memgov 是本机 CLI 记忆系统：保存证据，管理可独立复用的记忆，向人和外部 Agent 提供可靠的采集、召回、修订与历史。

现行流程是：工作材料保存为 Source，提炼为 Candidate，经核对后形成 Memory；Review 保存复核结果，版本和操作记录保留变更历史。SQLite 的 `state.db` 为唯一真相源，Markdown/JSON 为交换格式。

候选内容可由人或 Agent 提交，memgov 控制结构、证据定位、状态、版本和事务。源内容作为不可信资料处理，不执行其中的指令。

当前以 CLI 为主要入口。[本地管理台](../design/local-console-design.md)提供任务、记忆和运行查询、Agent 声明编辑及实时过程输出；统一服务支持显式重启和失败任务继续。页面通过本机 HTTP 接口复用业务与数据库，Desktop 外壳属于后续范围。钉钉接入支持所有者主动值守和群内 @ 专用 Agent 两种模式，现状见[接入设计](../design/dingtalk-integration-design.md)；安装和运行能力需分别核对。

最佳落地目标是工作事项从发现、关联背景、受控处理到交付验收形成闭环，并将可信经验用于下一次工作。后续设计和验收统一对齐[最佳落地场景与对齐标准](best-practice-scenarios.md)，不以接入工具或 Agent 数量替代业务效果。

旧三轴、记忆原子、卡片和战斗模型只保留在[历史存档](../archive/decisions/README.md)中。当前 Agent Skill 是调用 CLI 的使用说明，不是旧 Skill 运行框架。

参见 [架构](architecture.md)和[治理](../guides/governance.md)。

## 检索定位

### memgov 属于 RAG 吗，为什么不使用向量数据库？

广义上属于。当外部 Agent 先用 `recall` 取回记忆，再根据这些内容回答问题时，走的是“检索增强生成”模式。memgov 的记忆核心负责本地保存、检索与治理，可选值守运行时通过外部 Claude CLI 调用模型。当前检索使用全文索引，没有采用“文档切块 + embedding + 向量检索”的方案。

memgov 面向小规模、长期积累的个人记忆，例如个人约定、偏好、会什么、做过什么、操作流程和经验结论。它不以海量文档知识库和模糊语义问答为目标。

因此当前选择是：

- SQLite 是唯一真相源，保存正式记忆、证据、版本、状态和审计信息。
- SQLite FTS5 提供本地全文索引，优先满足姓名、域名、资源 ID、命令和明确关键词等精确召回。
- 不引入 embedding 和向量数据库，避免额外的模型依赖、索引更新、运维成本和相似但不准确的结果。
- 工作区、有效期、状态和证据约束比单纯提高语义相似度更重要。

这不是对向量检索能力的否定，而是与产品范围匹配的取舍。只有未来反复出现“记忆规模仍小，但用户换一种说法就明显召回不到”的情况，才考虑增加可重建的本地语义索引；它应作为 FTS 的补充，不能替代 SQLite 权威数据和治理过滤。

具体检索链路见[架构说明](architecture.md#检索)。
