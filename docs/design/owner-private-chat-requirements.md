# 本人私聊机器人：记忆盘点与任务执行

状态：根据 2026 年 9 月 15—16 日本人和“OpenClaw小钉-周守健”的私聊整理的开发需求。记忆盘点与工具诊断仍是开发准备范围；新增的热词和执行器技能配置已完成源码实现，见[语音热词与 Agent 技能配置](hotword-agent-skills-design.md)。实现依据和其余验收细节见[详细稿](owner-private-chat-requirements-detail.md)。

## 目标体验

本人直接问机器人“现在有多少条记忆”“最近一条是什么”，机器人应在本人可访问的范围内给出准确结果，说明统计范围、状态和时间含义。本人要求处理一个具体项目事项时，机器人应能找到已指明的本地仓库或 GitHub 仓库，完成可执行的准备和验证；若工具调用失败，应说明实际失败原因和未完成的动作。

## 本期范围

1. **记忆盘点。** 支持按工作区浏览正式记忆、统计条数，并分别查看最近创建和最近更新的记忆。列表与统计使用同一套工作区和状态过滤。不能把关键词召回的数量当作全库条数，也不能把材料提到的日期当作创建时间。
2. **本人私聊可用。** 让机器人按已配置的本人私聊能力调用上述只读命令；受控记忆工具拒绝命令时，应返回明确的原因和可用用法。普通私聊答复继续由机器人直接交付。
3. **项目事项可追踪。** 对本人明确指明的仓库，先核对位置和目标，再准备 issue 等外部操作。执行失败或结果未知时，记录真实状态和诊断信息；只有成功回读后才说“已提交”。对本人私聊的直接执行权限，以运行实例当时已应用的配置为准。

本期不把机器人提出的“CLI 缺少 `memory list` 或帮助”直接当作源码事实，也不把聊天历史中的 issue 授权用于本次真实提交。群内 Agent、主动值守及跨群联系沿用各自的权限边界。

## 实施顺序

先补齐记忆列表的时间与条数能力，并验证 CLI 与本人私聊入口的结果一致；再改进受控工具的帮助和错误返回；最后用一个明确的本地仓库与一个已授权的 issue 操作做真实私聊验收。真实钉钉收发、已安装二进制和实际运行进程分别核实，不以离线测试代替。

现有[记忆列表设计](memory-list-design.md)已覆盖时间排序；开发时把本稿中的统计和本人私聊使用场景纳入同一实施任务。
