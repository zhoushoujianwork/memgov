# 本人私聊机器人：实现依据与验收草案

范围以[主文档](owner-private-chat-requirements.md)为准。真实私聊原文、消息 ID、账号和会话标识只作为私有验收证据，不进入公开仓库。

## 需求与源码核对

- Owner 应能查询当前可见范围内的记忆总数、最近创建和最近更新，且回答必须说明工作区、状态与排序含义。
- `memory list` 和 CLI 帮助已存在；`doctor` 的数据库统计不能代替受可见范围约束的准确计数。
- 受控 Agent 包装器必须为允许的只读命令返回可诊断且脱敏的错误；完整 Bash 模式与受控模式依然使用不同的权限边界。
- 项目定位优先使用当前任务已绑定的工作区或精确 Git remote，不扫描整个 Home 目录。聊天正文中出现工具名不会自动扩大权限。

## 开发切入点

### 记忆列表、时间和统计

- 以[记忆列表设计与详细稿](memory-list-design.md)约定的 `created_at`、`updated_at` 语义实现时间排序与展示。`created_at` 是首次成为正式记忆的时间；`updated_at` 是最近正式变更时间。默认仍按更新时间倒序。
- 增加受工作区、状态和分类过滤约束的准确计数。可作为 `memory count` 命令或列表的总数元数据；实现时选择与现有 JSON 契约兼容的方式，避免把受 `--limit` 截断的列表长度当作总数。
- 本人私聊默认展示所用工作区、是否含 global、状态及排序依据；跨工作区总数和其他群的记忆不能由私聊问句或记忆正文自动扩大可见范围。候选、来源及已清除正文不计为可浏览的正式记忆。

### 私聊工具与诊断

- `direct_agent.go` 的受控记忆包装器可为只读 `memory list`、计数和对应帮助增加窄白名单，仍固定 home、workspace 和 actor；不为了解决“看帮助”开放配置、备份、清除或跨工作区能力。工具技能说明与包装器可执行命令保持一致。
- 受控包装器拒绝参数时返回结构化、非敏感的错误原因，而非只有 exit code 2；底层 CLI 失败时保留可安全披露的错误摘要。动作包装器也应区分文件不在会话目录、字段类型错误、当前尝试不匹配、CLI 拒绝与投递未知。诊断不得输出密钥、原始凭据或完整私聊正文。
- 项目定位优先使用本次任务已知的仓库路径或精确 Git remote，不做 Home 全盘搜索。`clawflow` 是否进入该 Agent 的已配置工具范围，需要单独检查安装与运行时配置；工具名出现在聊天原文中不能自动扩权。

## 验收案例

1. 在固定测试库中创建、修订和退役不同工作区的正式记忆：列表、计数、最近创建与最近更新符合过滤和真实系统时间；关键词召回结果不影响总数。
2. 本人私聊问“我有多少条”“最近创建的是哪条”：回复含准确范围、状态和时间依据；同样的问题在群 Agent 中不能读到本人私有记忆。
3. 受控入口对允许的 list/count/help 成功，对跨工作区、配置、备份和清除仍拒绝；错误可定位原因且无敏感信息。完整 Bash 模式使用真实 CLI，受控模式使用固定包装器，切换后旧会话正确重启。
4. 在真实私聊中明确目标仓库和 issue 内容，再按当时已应用的运行权限执行一次：准备、动作记录、实际提交、回读与交付分别可区分；失败或未知结果不报告成功，也不自动重复外部写入。

本稿对应[最佳落地场景](../architecture/best-practice-scenarios.md)的“事项闭环”“记忆可信”“权限随场景”和“交付可核对”。当前只完成需求提取、CLI/源码核对与开发范围准备；上述验收尚未执行。
