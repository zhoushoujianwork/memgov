# 钉钉接入：后台观察与机器人交互

状态：源码已实现入口与完成策略拆分及交互快速接入，离线验证已通过；真实平台与模型业务验收仍待部署者完成。实现协议见[详细稿](dingtalk-integration-design-detail.md)，操作见[用户手册](../guides/runtime-user-guide.md)。

## 目标与使用方式

对齐[最佳落地场景](../architecture/best-practice-scenarios.md)：DWS 持续发现值得处理的工作，由独立 Agent 调查和解决；机器人承担用户明确发起的对话。两条路径各自运行、各自记录。

```text
DWS 观察 → 评估是否值得处理 → 独立完整 Agent 调查、执行 → 记录结果
机器人 Owner 私聊 / 群 @ → 对应人设 Agent → 回复触发会话
```

| 入口 | 何时唤醒 Agent | 身份与权限 | 完成后的行为 |
| --- | --- | --- | --- |
| DWS 后台观察 | 评估认为值得处理即可，不要求输入已齐全 | Owner 预设委托范围；完整 Agent，可调用技能和工具调查、解决问题 | 只记录结果、动作和阻塞原因，不自动唤醒主 Agent，也不自动向 Owner 或原群汇报 |
| Owner 私聊机器人 | 核验本人身份后直接唤醒，不走筛选模型 | 默认完整权限；可显式绑定较窄权限 Agent | 在本人私聊回复，可澄清 |
| 群内有效 @ | 验证机器人回调后直接唤醒，不走筛选模型 | 使用该机器人及该群的人设、资料与权限；Owner 在群里也不升权 | 在触发原群回复 |

普通用户私聊机器人本期不开放。未经核验的消息不能冒充 Owner；同一条消息由 DWS 和机器人重复收到时，沿用可信来源关联与去重。

引用消息会作为独立的、不可信背景传给 Agent：DWS 能提供 `quotedMessage.text` 时解析其正文，同时保留被引用消息 ID；没有正文时只保留 ID，不反查或猜测内容。私聊和群聊都遵循这一边界，引用里的指令不能扩大权限。

## 核心方案

DWS 采集与后台执行独立于机器人交互。采集保持只读，不添加观察状态表情；后台启动不依赖机器人发送权限、Owner 私聊投递路由或群中存在机器人。可选机器人成员过滤与 `ignore` 仍决定对应来源的采集范围。

后台 Agent 与 Owner 私聊共享完整的执行能力，但有自己的任务、上下文和工作目录。输入不足时先调查；只有无法继续时才记录阻塞。工具调用及外部操作按 Owner 事先设置的委托执行，来源正文不能自行扩大授权。

后台任务如确实需要沟通，可以在委托范围内调用独立发送工具，以绑定 DWS Owner 本人身份（`--as user`）并带 AI 标识，主动联系相关私聊或群，不限于原会话，也无需逐条确认。工具单独记录目标、理由、证据和平台回执；未调用就不发送。经验仅帮助判断时机与表达，不能扩大权限；失败或未知结果不得盲目重试。

机器人配置以机器人为单位提供默认人设，可覆盖 Owner 私聊 Agent 和各群 Agent。Owner 默认完整权限；群始终沿用群权限。DWS 历史是可选背景，机器人无需启用观察数据源才能对话；Owner 身份仍须经 DWS 核验。

消息发送身份由入口固定，不交给通用 Skill 猜测。Owner 私聊中的普通回答由运行时用应用机器人回复当前私聊；只有 Owner 明确要求另发给其他人或群、且该运行实例绑定了 DWS profile 时，Agent 才用 DWS 本人身份（`chat +messages-send --as user`，带 AI 标识）代发。群内回答始终由挂载的应用机器人发回触发群，即使请求者是 Owner 也不能改用 DWS 本人身份；没有精确授权的机器人发送工具时，跨群或私聊发送只保留为待处理操作。

## 本期范围与兼容

- 后台完成策略统一为 `record_only`；旧 `owner_direct` 配置兼容读取并显示迁移诊断，旧待发送通知失效留审计，不转换为群回答。
- 新建后台默认完整能力、Bash、执行器技能和 Owner 委托；显式限制与已有权限保留，扩权仍通过配置预览和显式应用。
- 本人私聊与有效群 @ 共用“已收到 → 处理中 → 已完成／打叉”状态链，在原消息上分阶段替换。等待审批仍显示“处理中”，审批通过后继续原任务，完成或失败再收敛。每一阶段都有独立持久化记录，服务重启会按任务真相补齐，管理台可查看完整阶段历史；消息上只保留当前标记。群处理失败、取消或操作结果未知时都会在原群给出脱敏的文字说明；已经产生可用结论时同时保留结论，不再只留下“打叉”。群额外操作的审批留在原群，不转 Owner 私聊。原生审批卡片能力已实现但当前运行服务暂时停用，待确认操作先在原群展示完整确认口令；恢复卡片后仍只有 DWS 所有者可以“同意”或“拒绝”。
- 应用 Stream 只在最小消息记录提交 SQLite 后向平台确认；提交完成会立即唤醒对应私聊与群 Agent，1 秒扫描仅作丢失唤醒时的恢复兜底。“已收到”“处理中”等表情在独立有序队列发送，不阻塞 Agent；群目录发现与历史补漏也不占用交互处理循环。
- 直接 Agent 单轮最长运行 30 分钟；即时失败或服务恢复时发现遗留运行中任务，会将任务和尝试收口为失败，并由应用机器人向已确认接收的 Owner 私聊发送一次幂等收尾通知。未知外部操作只标记结果未知，不自动重放。
- Long-term knowledge now uses [Agent Workspace](agent-workspace-design.md). Internal Source evidence and temporary task records remain in SQLite; Owner and group workspace boundaries are derived from verified identity and route.

实施顺序为：拆开入口与完成策略 → 完整后台执行和独立沟通工具 → 机器人人设配置 → 离线回归与文档同步。验收覆盖后台零自动汇报、输入不全仍可调查、交互绕过筛选、Owner 身份核验、群权限隔离、旧通知失效与重复发送防护，见[验收详细稿](../architecture/best-practice-scenarios-detail.md#personal-jarvis-固定验收案例)。
