# 记忆列表、统计、时间排序与命令简写：实现细节草案

范围以[简明设计](memory-list-design.md)为准。`memory → m` 别名已实现；准确计数、时间字段、可选排序和表格展示仍为待实施方案。[本人私聊需求](owner-private-chat-requirements.md)要求在已授权范围内回答总数和最近一条。

## 当前实现依据

- `internal/cli/memory.go` 已注册 `memory list`，支持 `--status`、`--category`、`--all-workspaces` 和 `--limit`。
- `internal/core/search.go` 的 `ListMemories` 使用 `ORDER BY updated_at DESC,id LIMIT ?`，默认 50 条、最多 1000 条。核心查询未指定 status 时不限制生命周期，但现行 CLI 的 `memory list` 默认传 `active`。
- `memories.updated_at` 已保存更新时间；返回值却只解码 `document`，因此没有把更新时间带给调用方。
- 当前 Memory 正文没有系统创建、更新时间字段；首次版本的 `revisions.created_at` 可作为创建时间依据。
- `memory list --format text` 当前仍是 JSON 的文字展示，不是表格。不能把设计里的新展示方式写成现有功能。

## 子命令简写

`go.mod` 已依赖 `github.com/spf13/cobra v1.10.0`，`internal/cli/memory.go` 使用 `cobra.Command` 注册 memory。简写使用 Cobra 的 `Aliases`；`Short` 是帮助中的简短说明，不是命令别名。

已在同一个 memory 命令对象上增加别名，共用原命令树：

```go
memory := &cobra.Command{
    Use:     "memory",
    Aliases: []string{"m"},
    Short:   "正式记忆与历史",
}
```

- `memgov m list/show/history/...` 均经过原有 memory 子命令处理器，包含修改类子命令；别名不改变版本检查、工作区、幂等、审计或权限规则。
- 首期只登记 `memory → m`，不自动把所有命令首字母当别名，不启用前缀匹配。其他子命令以后也通过各自父命令下的 `Aliases` 明确声明。
- 同一父命令下，别名不能与兄弟命令的完整名称或别名重复。新增别名时验证冲突，不依赖注册先后来消歧。
- 审计和幂等键采用规范完整命令路径。当前公共写入层已使用 `cmd.CommandPath()`；保留该做法，不用原始 argv 或 CalledAs 构造业务命令身份。
- `memgov m --help`、`memgov m list --help` 能查看原命令帮助；帮助展示别名。验证既有 Shell 补全在别名后仍可补全子命令和参数，不新增 Shell alias 安装步骤。
- 完整命令保持稳定，现有脚本继续可用。JSON 结果除每次调用独立的 request_id 等运行元数据外，与完整命令一致。

## CLI 约定

| 参数 | 设计行为 |
| --- | --- |
| `--sort` | `updated_at`（默认）或 `created_at` |
| `--order` | `desc`（默认）或 `asc` |
| `--limit` | 默认 50，明确输入仅允许 1—1000 |
| `--format json` | 保持默认 envelope 及 `data` 数组，保留原有条目字段，增加创建、更新时间 |
| `--format text` | 简洁表格，显示排序时间、标题、分类、状态、版本、完整 ID；不展开正文 |
| `memory count` / `m count` | 与列表共享工作区、分类和状态过滤，默认只计 active；返回准确总数，不接受列表 `--limit` |

其余作用域、分类和状态参数保持现有含义。非法排序字段、方向、数量返回 `invalid_input`，不悄悄回退默认值。当前非正 limit 会回退 50，实施时一并改为明确报错并更新帮助。

`count` 与 `list` 使用同一作用域及生命周期过滤逻辑，在数据库内先排除不符合披露规则或已清除正文的条目，再统计正式记忆；不以 `list --limit` 的返回长度、`doctor` 的整库计数或关键词 `recall` 的命中数代替。JSON 返回总数及实际过滤范围，使机器人能说明它回答的是哪一个工作区和状态。跨工作区统计仍须显式授权。

排序 SQL 使用枚举映射，不拼接未经校验的参数。单独建立列表选项与返回类型，避免给关键词 search/recall 引入无关排序行为。首期没有 offset、cursor、日期范围或 observed_at 排序；不借此重做搜索。

## 时间语义

| 字段 | 来源及含义 |
| --- | --- |
| `created_at` | 该记忆 version=1 的历史记录时间，即首次应用为正式记忆的时间；不使用 MIN(所有时间) 推测 |
| `updated_at` | 当前 `memories.updated_at`；创建、内容修订、退役、恢复等正式变更更新它 |
| `observed_at` | 正文中的业务观察时间，可能未知；此次不参与排序 |

来源导入和候选提交尚未创建正式记忆，不计入列表。读取、检索、建立索引和重复幂等调用不能刷新更新时间；备份恢复保留当时的记忆时间，不把恢复文件时间当更新时间。

展示和比较统一使用 UTC。当前时间写入采用 RFC3339Nano，存在可变小数位；不能直接依赖不同精度或不同时区偏移的原始文本排序。排序前规范为 UTC 固定精度时间键，保留实际时间精度；未来增加索引时也使用同样的规范。

正常记录的首次版本应存在。若历史缺失，创建时间返回 null、排在已知时间之后，不用最近更新时间或当前时间伪造；完整性问题交给 doctor 报告。非法时间也不能静默转换成“现在”。具体诊断字段在实现时按现有错误协议细化。

## 查询与展示

1. 先执行工作区、分类、状态和清除规则，选择每条正式记忆的当前版本。
2. 关联首次版本时间，读取当前更新时间；统一时间键。
3. 按所选时间升/降序排列，时间相同固定按完整 memory ID 升序，未知时间固定在末尾。
4. 排序后应用 limit，不能先取部分行再在内存中排序，导致遗漏真正最新的记忆。
5. 在同一个只读快照中完成本次列表。跨次调用发生写入时结果可以变化，不承诺跨请求分页快照。

返回时间属于列表读取元数据，使用独立的列表返回结构，避免改写 Memory document、候选摘要指纹或不可变历史。不要让调用方填写系统时间。旧数组输出继续可用；新字段是增量元数据，不将 `data` 改为分页对象。

text 表格表头注明当前排序字段、方向与 UTC；长标题只在显示时截断，转义换行和终端控制字符，JSON 保留原值。空结果时 JSON 为 `[]`，text 明确显示“没有匹配的记忆”。

## 数据库与实现范围

首选复用 memories 和 revisions，派生列表时间，不为展示需求重写历史数据。根据数据量选择规范时间键的查询或派生索引；如果确需持久化派生列，追加新的 Schema 迁移，禁止修改已发布迁移脚本。

不要给包含系统时间的列表对象直接开放写入；把列表项当作修订模板时仍需提取现行 Candidate 支持的 Memory 字段。列表是本地管理入口，不代表 active 记忆仍在有效期内，也不提供远程会话披露权限；机器人继续走既有受众约束入口。

## 验收用例

- `memory list` 与 `m list` 在相同快照和参数下得到相同业务结果；show、history 和帮助同样可用，未知缩写仍明确报错。
- 使用同一幂等键分别通过 `memory retire` 和 `m retire` 请求同一次变更，只产生一次版本及审计操作；不同输入仍返回冲突。失败退出码和作用域拒绝不因别名而改变。
- 检查完整命令名与别名冲突，以及已支持 Shell 的补全行为；帮助和补全不初始化数据库。
- 不传排序参数时默认 updated_at desc，与现有默认意图一致；显示值与实际排序键对应。
- 新增 A、B，再修订 A：按创建倒序为 B、A，按更新倒序为 A、B；正序相反。
- 退役和恢复改变更新时间，创建时间不变；未筛状态时仍能看到退役记忆。
- 同时间多条记忆重复查询顺序稳定；不同 UTC 偏移和小数精度按真实先后排序。
- 未知创建时间不被伪造，始终排末尾；缺失首次版本能被检查发现。
- 工作区加 global、显式跨工作区、分类和状态过滤在排序前生效；清除正文不因列表重新出现。
- `memory count` 和 `m count` 在相同过滤下相等，且计数与不截断列表一致；列表的 `--limit`、`recall` 命中数和整库 `doctor` 数值不能改变过滤后的计数。
- limit 边界和非法参数返回正确退出码；候选、不符合筛选的记忆不占返回条数。
- JSON 原有字段可用，包含只读时间；text 清晰显示列表、空结果和长标题。
- 测试使用固定时间与临时数据根，不靠 sleep 制造时间差；普通列表不写审计、不更新记忆、不隐式升级数据库。

别名已加入现行 CLI 使用文档。其余时间排序和展示能力验收通过后再更新使用说明；设计阶段不提前把它们列为已支持功能。
