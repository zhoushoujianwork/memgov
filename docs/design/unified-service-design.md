# 统一本地服务

状态：统一服务、Web 重启及 macOS 系统托管已在源码实现（2026-09-17）；验证与安装边界见[详细稿](unified-service-design-detail.md#验证)。

采集、本人私聊、群内 @ 和主动值守由一个 memgov 服务统一运行。用户只启动、停止和重启服务；内部运行记录继续保存任务恢复和审计信息。

## 使用

先按现有接入流程验证通道并应用配置。macOS 长期运行安装一次系统托管：

```bash
memgov service install --config ~/.memgov/config.yaml
memgov service status
memgov service restart  # 系统后台重启，命令完成后返回
memgov service stop     # 停止并关闭自动拉起；service start 恢复
```

安装会接管当前数据目录的旧服务；关闭终端不影响运行。系统在用户登录后自动启动服务，进程退出后自动拉起；程序替换完成后会自动加载新版本。`make install` 已采用原子替换。手动更新也应先构建新文件再改名覆盖安装路径；新文件暂时缺失时旧服务继续运行。

托管服务遇到新程序需要升级数据库时，先保存并校验升级前备份，再自动迁移并启动。备份保存在数据目录的 `backups/service-upgrades/`。备份失败、数据库被其他进程占用或版本不受支持时不会强行升级，具体原因写入启动日志。普通前台命令仍需显式执行 `memgov init` 升级。

管理台默认使用本机 8787 端口；安装时用 `--port` 设置固定端口，`--no-ui` 关闭管理台。修改托管配置或程序路径时重新执行 `service install`；`service uninstall` 停止并移除托管，保留数据及日志。`service status` 可查看托管文件与启动日志路径。

未安装托管时，`service start` / `restart` 仍为前台运行，Ctrl-C 停止；`restart` 会迁移旧独立模块。前台模式支持 `--port 0`。本期系统托管只支持 macOS 当前用户登录会话，不保证注销、关机或睡眠期间持续在线；Linux 系统托管另行实现。

## 核心行为与范围

- 一个服务进程管理已启用的数据源及应用。本人私聊和群内 @ 共用同一个机器人通道接收器。
- 本人、群专用 Agent 和主动值守保留各自身份、上下文与权限。统一运行不扩大跨群披露范围。
- 管理台在一个统一服务下，将“通道与采集”和“处理 Agent”分组展示；任务按处理 Agent 筛选，不把内部模块误示为独立常驻进程。模块故障单独恢复；权限或配置冲突需要修正后重启。
- Web 各页面的侧栏左下角可一键重启统一服务，等待模块退出后加载已安装程序，保留页面地址及端口并自动重连。旧实例需先更新程序并从终端重启一次才有此能力；独立 `ui` 诊断页的按钮禁用，不控制统一服务。
- 模块暂停、恢复仍可单独控制；服务停止会等待全部模块退出。同一数据目录不能重复启动统一服务。
- 服务加载数据库中已应用的配置；修改 YAML 后仍需预览和应用。`owner_private.runtime` 可省略，内部默认绑定现有本人私聊配置 `owner-private`。

本期统一生命周期、接收管理及 macOS 系统恢复，复用现有 Agent 执行逻辑。群内多轮持续会话另行处理。低层 `runtime`、`data-source` 命令保留兼容及诊断用途。

对应[最佳落地场景](../architecture/best-practice-scenarios.md)的所有者值守与群专用 Agent；本次验收重点是统一运行和故障隔离，真实业务效果仍需场景验收。实现与验证见[详细稿](unified-service-design-detail.md)。
