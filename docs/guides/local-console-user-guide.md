# 本地管理台使用说明

Owner Assistant 运行页分别显示根任务、子 Agent、共享分析/执行/审查槽位、队列与覆盖缺口；任务详情显示阶段、截止、控制心跳、上下文来源、权限版本和实际模型输出时间。心跳不代表模型有进展，“业务完成”也不代表记忆已应用。记忆失败单独显示原因；具体破坏性操作显示提案和 Owner 确认口令。Owner proactive 只在有结果、阻塞或需要确认时通知；群 Jarvis 的任务与投递仍留在原群。

轻量 Web 管理台提供记忆卡片、任务执行记录、统一服务模块和数据源查询，并可编辑、删除 YAML Agent 声明，不需要安装前端运行环境。实现方案见[主设计](../design/local-console-design.md)，Desktop 外壳属于后续范围。

## 启动

macOS 长期运行使用唯一活动配置 `memgov service install --config ~/.memgov/config.yaml`，由系统托管 Owner Assistant、群 Jarvis 和管理台；随后访问本机 8787 端口。关闭浏览器或终端不会停止托管服务；`service stop` 停止并关闭自动拉起，`service start` 恢复。前台调试仍可使用 `service start --config ~/.memgov/config.yaml --open`。`config.dual.yaml` 只保留为迁移备份。详见[统一本地服务](../design/unified-service-design.md)。

更新、启动和进程迁移步骤统一见[服务说明](../design/unified-service-design.md#使用)；数据库升级见[任务继续说明](../design/task-continuation.md#首次更新)。

统一服务的 Web 侧栏左下角提供「重启服务」按钮，所有页面可用；旧实例需先更新程序并从终端重启一次。点击后先等待采集和 Agent 退出，再加载原安装路径的程序；保留当前页面地址及端口，页面自动重连。重启不会编译或安装新版本，也不会自动应用尚未应用的 YAML 修改。单独运行 `memgov ui` 的诊断页面将按钮禁用，并提示在终端重启。

重启中断的任务可在「任务」页选择失败记录并点击「继续任务」：恢复原会话或检查原请求及已有进度后继续，同时恢复所属运行模块。原文失效或存在未知外部结果时不提供可执行按钮。此入口已在源码实现；本次 Cyber owner 需要 Schema 26，数据库升级沿用显式迁移流程，详见[中断后继续任务](../design/task-continuation.md)。

Owner 根任务分别查看直接结果、子 Agent 汇总与「Agent 沟通记录」。沟通记录列出身份、上下文来源、权限版本、对象、理由及投递状态；平台受理不等于确认送达，未知结果应先核对回执。群 Jarvis 的回答和确认仍显示为原群交付，不转发到 Owner 私聊。

下面的 `ui` 是单独启动管理台的兼容诊断入口。
构建最新源码后：

```bash
make install
.memgov/bin/memgov --home ~/.memgov --config ~/.memgov/config.yaml ui --open
```

`--home` 与 `--config` 使用你已有实例的路径；未使用双模式配置时可省略 `--config`。命令不初始化或迁移数据库，不启动采集和 Agent。数据库版本不匹配时，需要先按错误提示单独处理，不能把打开页面当作数据库升级。

默认监听 `127.0.0.1:8787`；端口被占用时用 `--port 0` 自动选择，或指定其他端口。直接打开 `http://127.0.0.1:8787/` 即可访问，无需 token 或登录 cookie。刷新页面和服务重启后均可用同一地址访问；自动选端口时使用终端显示的地址。

任务 `/tasks`、记忆 `/memories`、运行 `/running`、设置 `/settings` 使用独立路径，可直接打开或收藏。侧栏切换同步更新地址，浏览器前进、后退及刷新恢复对应页面；根地址默认进入任务页。URL 本期只定位页面，不保存筛选、分页或详情。

按 Ctrl-C 只停止这个管理台服务，原有采集与 Agent 继续按各自生命周期运行。界面也可以放入后续 Desktop WebView，页面不依赖桌面框架。

页面中的系统时间显示“几分钟前”等相对时间并自动更新；悬停可查看完整时间及其时区。未记录的时间不会推断，未来有效期显示“多久后”。窄屏重启入口位于导航下方。

左下角版本区显示运行版本和构建指纹。“本机已同步”仅表示运行程序与安装文件一致；GitHub tag 检查单独判断是否存在新版，包含 `rc` 等预发布版本，不依赖 Release。页面连接后自动检查一次，可点击“检查更新”；成功结果缓存 15 分钟，无 tag 或失败缓存 1 分钟，悬停来源说明可查看检查时间。私有仓库需要服务环境中可用且已登录的 `gh`；没有登录时不会借用其他凭据。远端暂无可比较 tag 时如实显示，不创建或推送 tag。

## 查看任务

首页默认显示未完成、未取消记录，支持按状态和运行实例筛选，使用下一页查看更多记录。私聊问答也会形成任务记录，页面标明为“本人私聊轮次”，并不代表每条记录都是独立主动工作事项。

选择一条记录后，右侧显示原始请求、来源 ID、执行尝试、模型、配置版本、处理结果、投递状态和相关诊断日志。可以复制包含当前实例路径的 CLI 查询命令。重试、取消和模块启停按钮仍未接入；统一服务重启与失败任务继续已由独立控制入口提供。

任务的 `running` 是数据库状态；近期心跳说明运行包装进程最近有上报，不证明模型在持续调用工具。任务 running 而实例记录已停止或没有可验证心跳时，会标为需要关注。没有上报心跳的旧实例显示“进程状态未验证”，运行版本未知；管理台不会为此自动重启。

处理结果和投递状态分别显示：没有投递记录时，不能据任务 completed 推断机器人回复已送达。诊断日志只显示结构化字段；Web Terminal 另展示脱敏公开文字与工具事件，不作为任务完成或送达的证明。

## 运行与设置

运行页首先展示统一服务 PID、心跳及模块状态，再展示本人私聊、主动值守及群 Agent 的记录状态、待处理数量和近期心跳。数据源卡片展示接收租约、私聊启用时间、七天策略、最近收流、发现覆盖、清理结果和各会话缺口；有效租约不等于双方消息均已验证收流。

设置页显示已应用的 Agent 策略，并只读发现 Claude 技能。技能发现使用约 30 秒缓存，扫描在后台进行；首次或更新扫描显示诊断，声明编辑仍可加载。编辑路径尚在扫描时，需要稍后重新预览；磁盘清单不能代替某个既有持续会话的加载快照。管理台服务构建、其磁盘二进制构建、运行实例报告构建和配置版本分别提供，不能用磁盘最新版本推断旧进程也已经更新。

## 编辑、删除 Agent

设置页的 **Agent 声明** 来自当前 YAML，包含未绑定的 Agent。**运行时已应用策略** 来自数据库，两者分别展示。

1. 点击“编辑 Agent”，修改模型、技能继承和路径、记忆范围、能力、目录、Bash 或外部动作策略。
2. 点击“预览变更”，检查变化。路径和声明经过现有配置及技能检查；改动表单后必须重新预览。
3. 点击“保存到 YAML”。界面显示待应用，运行中的配置保持原状态。
4. 复制 `config plan` 命令，按返回的版本、摘要和阻塞项执行 `config apply-runtime`。能力扩大和边界变化继续要求现有授权理由；服务不会自动停机或接管进程。

“删除 Agent”仅用于没有 YAML 或已应用引用的声明。被引用时按钮禁用，显示引用位置；先解除绑定并应用，再删除。删除不会清理任务、正式记忆、Preset 或技能文件。未声明的默认 Agent 仍通过 CLI 管理，不会由页面自动创建或改绑。

保存按 YAML 内容版本检查，多窗口过期编辑会拒绝保存。符号链接指向的配置更新其目标，保留链接和原文件权限。尚未保存的编辑不进入浏览器持久存储，页面失联或进入后台时关闭编辑窗口；请在离开前保存。

## 刷新与正文

任务详情提供只读 **Web Terminal**，运行任务自动展开，实时查看 Claude 文字、工具调用和工具结果；支持暂停跟随和切换执行尝试。更新服务后的新调用才开始采集，旧调用无法回补，详见[实时执行过程](../design/task-terminal.md)。

可见页面约每 3 秒查询状态，数据变化才重绘；展开日志约每 9 秒查询增量。页面进入后台时暂停查询并清空已展示正文，回前台重新读取。失联后清空正文、显示错误并退避重试，不把旧状态当作实时观测。

任务来源按数据源保留规则即时过滤，未物理清理的过期内容也不返回。关联来源过期或不可用时，列表标题、预览、任务结果及执行摘要保守隐藏，保留状态、消息和来源定位；无来源关联的自由文本结果也隐藏。到期响应携带的截止时间会清空浏览器内存中的正文。页面不持久缓存聊天或结果，不承诺删除用户自行复制的内容。

只监听本机地址，并校验 Host、Origin 和跨站请求标记；本期没有群成员或多人 Web 入口。管理台请求不改变群 Agent 的私聊访问权限。


## 记忆卡片与执行记录

点击“记忆”浏览正式记忆。默认是全局有效记忆；选择工作区会同时包含该工作区和全局记忆，跨工作区查看需显式选择“全部工作区”。支持分类、状态和全文搜索，每页 24 条、最近更新在前。

点击卡片阅读完整正文，展开“适用条件与标签”“来源与证据”“版本历史”核对依据。卡面摘要截断不影响正文；Esc 或关闭按钮返回原位置。记忆页只读，不提供编辑、合卡或套牌。

任务页中的“执行记录”按任务归集各次尝试、时间、摘要、错误及已记录产物。“执行过程”可查看可用尝试的只读终端输出，结果与交付状态分别核对；未记录用户验收时会明确提示。请求或任务版本变化、来源过期或撤回时，旧输出隐藏并保留执行元数据。

这些能力已在源码实现；请核对当前二进制和运行服务版本。仅更新源码不会更新已启动的页面服务。

## 前端开发

前端源码位于 `web/`，采用 React、TypeScript 和 Vite。已有本地服务运行后，在仓库根目录执行 `make web-dev`，打开 `http://127.0.0.1:5178/` 进行热更新开发；生产仍用 `make build` 生成内嵌页面的 Go 二进制，系统托管会自动加载替换后的程序，前台服务需要显式重启；之后刷新浏览器加载新页面。开发环境需要 Node 22.16+ 和 npm，最终用户运行无需 Node。完整步骤见 [Web 开发说明](../../web/README.md)。
